# Домашнее задание №1 «Создание ИИ-агентов с нуля» — вариант A

Мини-трекер учебных задач на неделю. Цель работы — сравнить прямую разработку по запросу к ИИ с разработкой по заранее подготовленной спецификации. В варианте A каждая версия представляет собой самостоятельный HTML-файл со встроенными CSS и JavaScript.

## Возможности мини-трекера

- Добавление задачи с названием и оценкой времени в часах.
- Удаление задач, установка и снятие отметки выполнения.
- Просмотр всех задач или только активных.
- Подсчёт общих и выполненных часов, отображение процента прогресса и полосы прогресса.
- Проверка ввода и сообщения об ошибках.

Стартовый набор: «Чтение» — 2 ч, выполнено; «Практика» — 4 ч, не выполнено; «Повторение» — 2 ч, не выполнено. Ожидаемые начальные показатели: 8 ч всего, 2 ч выполнено, 25% прогресса. Фильтр меняет только видимый список, показатели рассчитываются по всем задачам.

Особенности текущих файлов установлены по исходному коду:

| Возможность | V1 | V2 |
|---|---|---|
| Часы в форме | От 0,1 до 10000, шаг 0,1 | От 0,5 до 24, шаг 0,5 по спецификации |
| Сообщения об ошибках | Встроенная проверка браузера и сообщение для пробельного названия | Сообщения рядом с полями; при ошибке ввод сохраняется |
| Фильтры | Все, активные, готовые | Все, активные |
| Сохранение | localStorage, при недоступности — работа в памяти с уведомлением | Только в памяти; перезагрузка восстанавливает стартовый пример |

Обе версии содержат адаптивные стили. Спецификация требует читаемости при ширине 390 px без горизонтального скролла; наличие стилей само по себе не является результатом проверки в браузере.

## Структура проекта

```text
.
├── tracker-v1.html       — версия для подхода с прямым запросом
├── tracker-v2.html       — версия для подхода по спецификации
├── proposal.md           — цель, границы и варианты поставки
├── design.md             — данные, валидация, расчёты и интерфейс
├── tasks.md              — чек-лист реализации и предложенных проверок
├── specs/
│   └── tracker/
│       └── spec.md       — требования и сценарии в формате OpenSpec
├── report.md             — таблица результатов T1–T5 до исправлений
├── prompts.txt           — сведения о запросах и пробелах в истории
└── README.md             — описание проекта и инструкция запуска
```

Документы спецификации также описывают вариант B, но в этом проекте представлен вариант A.

## Запуск

1. Откройте папку проекта.
2. Дважды щёлкните `tracker-v1.html` или `tracker-v2.html`, либо выберите «Открыть с помощью» и браузер.
3. Разрешите выполнение JavaScript, если оно отключено. Для сравнения откройте версии в отдельных вкладках.

Установка пакетов, сборка, сервер, API-ключи и подключение к интернету для работы трекера не требуются: код и стили находятся внутри HTML-файлов, внешних библиотек и CDN нет.

V1 может восстановить ранее сохранённые задачи. Для проверки стартового примера при необходимости удалите только ключ `study-task-tracker-v1` из localStorage этой страницы через инструменты разработчика и перезагрузите страницу. Это удалит сохранённые задачи V1. V2 возвращается к стартовому примеру при обычной перезагрузке.

## Два подхода к разработке

**Прямой запрос — V1.** Подход предполагает создание приложения непосредственно по описанию задачи, без отдельного этапа спецификации. Его артефакт в сравнении — [tracker-v1.html](tracker-v1.html). Фактический текст исходного запроса не сохранён.

**Разработка по спецификации — V2.** Сначала формулируются цель и границы в [proposal.md](proposal.md), правила реализации в [design.md](design.md), требования и сценарии в [specs/tracker/spec.md](specs/tracker/spec.md), а также чек-лист в [tasks.md](tasks.md). Отдельный этап — реализация [tracker-v2.html](tracker-v2.html) по этим документам. Фактические тексты запросов на спецификацию и реализацию не сохранены.

Использована спецификация в формате OpenSpec без запуска OpenSpec CLI. В `tasks.md` также прямо указано, что валидатор не запускался. Это применение формата документов, без подтверждённой проверки средствами CLI.

Сведения об исходных запросах собраны в [prompts.txt](prompts.txt). Методички и текстов диалогов в проекте нет, поэтому точные шаблоны и неизвестные обращения не восстановлены предположительно.

## Проверки T1–T5

Нумерация соответствует [отчёту](report.md), а действия и ожидаемое поведение раскрыты по спецификации. Ниже приведены сценарии проверки, а не новые результаты запуска.

Перед независимым сценарием восстановите стартовый набор. В частности, T3 выполняется на исходном состоянии, а не после T2.

| Тест | Действие | Ожидаемый результат |
|---|---|---|
| T1 | Открыть стартовый пример | Всего 8 ч, выполнено 2 ч, прогресс 25% |
| T2 | На стартовом примере отметить «Практику» выполненной | Всего 8 ч, выполнено 6 ч, прогресс 75% |
| T3 | На неизменённом стартовом примере включить фильтр «Активные» | Видны «Практика» и «Повторение»; показатели остаются 8 ч, 2 ч, 25% |
| T4 | Попытаться добавить задачу с пустым или пробельным названием, пустыми либо отрицательными часами; по спецификации также проверить диапазон 0,5–24 и шаг 0,5 | Недопустимая задача не добавляется; ошибки отображаются. Спецификация требует ошибок рядом с полями и сохранения ввода |
| T5 | Удалить все задачи | Всего 0 ч, выполнено 0 ч, прогресс 0%; нет NaN, Infinity и ошибок |

В отчёте T4 описан только общей фразой «Ошибки ввода отображаются»: подробный набор фактически проверенных значений не указан. Расширенное описание T4 выше задаёт проверку требований, но не подтверждает её выполнение.

## Отчёт и границы подтверждённых сведений

Результаты сохранены в [report.md](report.md) в столбцах «V1 до исправлений» и «V2 до исправлений». Для T2 у V1 записаны 6 выполненных часов из 8 и 67%, у V2 — 75%. Сейчас исходный код V1 уже вычисляет процент по формуле `Math.round(doneHours / total * 100)`. Поэтому таблицу до исправлений нельзя считать результатом повторной проверки текущих файлов.

В `tasks.md` сохранён статус этапа спецификации: код и исполняемые проверки ещё не выполнены. При этом в проекте уже есть HTML-файлы и отдельный отчёт; чек-лист не отражает их наличие. При подготовке этой документации приложения в браузере и тесты не запускались. Тексты запросов на исправления, результаты повторных проверок, даты, длительность работы и количество обращений не подтверждены доступными материалами.
